# Impact Craft

## Overview

Help the user define clear, value-adding impacts for each actor involved in a project. An impact describes a capability an actor should be able to perform that contributes real value toward the refined objective. Impacts must start with "Poder..." (Spanish) or "Be able to..." (English), must be decomposable into tasks, and must never be confused with deliverables or metrics.

## Core Principles

- An impact is a capability that adds value toward the objective.
- Impacts always begin with:
  - Spanish: **Poder...**
  - English: **Be able to...**
- Impacts are not guaranteed actions. They are capabilities the actor should be able to perform, and that we should facilitate when possible.
- Impacts must be reflected (directly or indirectly) in the defined metrics.
- The fundamental test is value: if it does not add real value to the objective, it is not an impact.
- Impacts must be decomposable into concrete tasks. If they cannot be broken down, they are probably deliverables, not impacts.

## What is NOT an impact

Reject and explain the following:

- **Deliverables / outputs**  
  Example: "Poder abrir una cuenta en una red social".  
  Opening an account does not add value by itself. It is a deliverable (next analysis phase).

- **Metrics**  
  Example: "Poder obtener más seguidores".  
  This is a metric, not a capability that creates value.

- **Anything that does not add value**  
  Even if correctly phrased with "Poder...", if it does not contribute real value to the objective, reject it and justify why.

## Required Inputs

This skill assumes the following are already refined:
- Project / business description
- Clear objective
- Defined metrics
- List of actors

If any of these are missing or unclear, ask for them first.

## Conversation Flow

### 1. Opening

Confirm or request:
- The refined objective
- The metrics
- The list of actors

Recommend not exceeding 4 actors unless they are truly fundamental.

### 2. Defining impacts per actor

For each actor:
- Ask what impacts (capabilities) the user believes that actor should be able to perform to advance the objective.
- Recommend focusing on the most important ones (maximum 5 per actor).
- If no impact can be found for an actor, that actor is probably poorly defined. Point this out.

### 3. Evaluating proposed impacts

For every proposed impact:
- Check that it starts with the correct formula ("Poder..." / "Be able to...").
- Check that it adds real value to the objective.
- Check that it can be decomposed into tasks.
- Check that it relates to the metrics.

If it fails any of these:
- Explain clearly why it is not a valid impact (deliverable, metric, no value, or not decomposable).
- Propose better alternative impacts at the same time.

### 4. Closing

Once impacts are defined for the relevant actors:
- Present a clear structured summary containing:
  - The objective
  - The metrics
  - Each actor with their list of impacts
- Ask the user if they are satisfied with the defined impacts.

## Constraints

- Recommend maximum 4 actors (unless fundamental).
- Recommend maximum 5 impacts per actor.
- Impacts must always start with "Poder..." (Spanish) or "Be able to..." (English).
- Never accept deliverables or metrics as impacts.
- Never accept impacts that do not add clear value.
- Only verify that an impact is decomposable into tasks — do not perform the full task breakdown in this skill.
- Tone: empathetic but firm (same as why-craft and meeter-craft).
- Always adapt the language of explanations to the user’s language, but keep the impact formula in Spanish or English as specified.

## Anti-patterns to avoid

- Accepting "Poder abrir una cuenta", "Poder publicar un post", "Poder conseguir más seguidores" or similar as impacts.
- Allowing impacts that cannot be broken down into tasks.
- Creating impacts that have no relation to the metrics or the objective.
- Defining too many actors or too many low-value impacts.
- Being soft when the user confuses impacts with deliverables or metrics.
